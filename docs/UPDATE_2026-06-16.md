# Actualizacion Nexus IA - 2026-06-16

Este documento resume el estado actual del proyecto despues de la implementacion
de seguridad SaaS, roles, permisos, planes, consumo IA, dashboards por rol,
paneles Super Admin/Owner, onboarding, reportes, atencion humana, WhatsApp y
pedidos.

## Estado general

Nexus IA es una plataforma SaaS multiempresa para ventas conversacionales por
WhatsApp con IA. Cada empresa opera como tenant independiente mediante
`empresa_id` o `tenant_id`, con roles, permisos, limites de plan y datos
filtrados por empresa.

El proyecto ya incluye:

- Backend Express modular.
- Frontend React/Vite.
- MySQL con esquema multiempresa.
- Autenticacion JWT.
- Roles y permisos backend/frontend.
- Panel Super Admin.
- Panel Owner.
- Dashboard distinto por rol.
- Configuracion IA por empresa.
- WhatsApp por empresa.
- Conversaciones con modo atencion humana.
- Productos, servicios, clientes/leads, pedidos y reportes.
- Onboarding para nuevas empresas.
- Planes SaaS y consumo IA.
- Seguridad reforzada.
- Tests unitarios e integracion con DB.

## Seguridad SaaS

Se reforzo:

- `requireAuth` para validar usuario autenticado.
- `requirePermission(permission)` para proteger acciones por permiso.
- `requireRole(role)` para rutas estrictas.
- Validacion obligatoria de tenant en rutas privadas.
- Bloqueo de acceso cruzado entre empresas.
- `super_admin` puede operar globalmente.
- Roles no globales quedan amarrados a su `empresa_id`.
- Sanitizacion global de inputs.
- Rate limiting basico.
- Redaccion de datos sensibles en logs HTTP.
- Auditoria de acciones importantes.
- `password_hash` no se devuelve en respuestas.
- QR/tokens sensibles de WhatsApp no se exponen en listados.
- Datos sensibles de sesion WhatsApp se cifran en reposo con AES-256-GCM.

Archivos clave:

- `backend/src/app.js`
- `backend/src/middlewares/sanitize-input.middleware.js`
- `backend/src/middlewares/rate-limit.middleware.js`
- `backend/src/middlewares/request-logger.middleware.js`
- `backend/src/utils/crypto-field.js`
- `backend/src/modules/audit/audit.service.js`

Variable recomendada para produccion:

```env
FIELD_ENCRYPTION_KEY=secreto_largo_para_cifrado_de_campos
```

## Multiempresa y tenant scope

Regla central:

- Toda consulta operativa debe filtrar por `empresa_id` o `tenant_id`.
- Para `owner`, `seller`, `support` y `viewer`, el backend ignora o bloquea
  intentos de acceder a otra empresa.
- Para `super_admin`, algunas rutas permiten seleccionar empresa explicitamente.

Helpers principales:

- `resolveScopedEmpresaId`
- `companyScopeCondition`
- `appendCompanyScope`
- `requireTenantScope`
- `attachTenantScope`

## Onboarding de nueva empresa

Flujo para `super_admin`:

1. Datos del negocio.
2. Crear primer usuario owner.
3. Elegir plan.
4. Configurar mensaje de bienvenida.
5. Configurar nombre de IA.
6. Agregar primeros productos.
7. Conectar WhatsApp o dejar pendiente.
8. Mostrar checklist.

El backend crea la empresa y reutiliza el `empresa_id` real para owner,
configuracion y productos.

Endpoint:

```http
POST /api/onboarding/companies
```

Archivos:

- `backend/src/modules/onboarding/`

## IA + MCP

La IA no consulta MySQL ni ejecuta SQL. Solo clasifica el mensaje y devuelve JSON
estructurado validado por backend.

Herramientas MCP:

- `buscar_productos`
- `obtener_producto`
- `buscar_servicios`
- `obtener_servicio`
- `obtener_categorias`
- `obtener_promociones`
- `obtener_configuracion_empresa`
- `crear_lead`
- `registrar_intencion_compra`
- `guardar_conversacion`
- `crear_pedido`

Reglas:

- No se aceptan parametros SQL.
- Se rechazan parametros desconocidos.
- Cada herramienta valida `empresa_id`.
- El backend construye la respuesta final con datos reales.

Archivos:

- `backend/src/ai/intentInterpreter.js`
- `backend/src/mcp/mcpClient.js`
